🚨 Critical & Data Loss Bugs 5 Bugs

BUG 1.1 Data Loss

Daily Workout Log Overwrite

Saving a workout deletes all existing records on that date from the database before adding the new entries.

User's Point of View: "If I log my morning run, and later in the evening I log a gym session, my morning run is completely wiped out without any warning. I can only save one workout per day."
  • Affected File: app/workout/page.tsx (line 509)
  • Root Cause: `supabase.from('workout_log').delete().eq('date', date)` deletes the entire day's logs before inserting new sets.
BUG 1.2 Data Loss

Second Brain Quote Truncation

The block parser parser discards subsequent lines of blockquote notes during deserialization.

User's Point of View: "When I write a multi-line quote in my notes, the next time I open that note, all lines after the first line have vanished. My data is permanently lost."
  • Affected File: lib/blockParser.ts (line 156)
  • Root Cause: Split-line quote parser reads only index `0` and ignores multi-line quote markers.
BUG 1.3 Formatting

Bold Text to List Conversion

Paragraph blocks starting with bold markdown characters (asterisk/dash) are mistranslated as bullet lists.

User's Point of View: "Whenever I write a paragraph starting with bold markdown text like `* This is bold *`, the editor turns the entire paragraph into a bullet list item when I reopen it."
  • Affected File: lib/blockParser.ts (line 123)
  • Root Cause: Pattern match evaluates any block starting with `* ` or `- ` as lists, ignoring bold markdown text tags.
BUG 1.4 Data Loss

Recurring Task Subtasks Discard

Checking a recurring parent task complete creates the next scheduled task instance but abandons its checklist subtasks.

User's Point of View: "When I complete a recurring task, it schedules the next occurrence, but all of its subtask checklists disappear. The new task is empty, meaning I have to re-enter all my subtasks every time."
  • Affected File: app/tasks/today/page.tsx (line 320)
  • Root Cause: Cloned recurrence creation lacks subtask copying logic, leaving subtasks associated with the completed parent ID.
BUG 1.5 Logic

Streaks Preserved via Unlogged Days

Habit consistency reports iterate only over entered logs, allowing users to preserve streaks by not entering data on failed days.

User's Point of View: "If I skip my habit on Tuesday and simply do not log it, my streak continues on Wednesday as if Tuesday never happened. My streak calculation is fake because it ignores days I forgot to log."
  • Affected File: app/reports/habits/page.tsx (line 856)
  • Root Cause: Stretches are evaluated based on logs present in the DB rather than consecutive calendar dates.

📅 Timezone & Calendar Bugs 3 Bugs

BUG 2.1 Timezone

Subscription Billing Due Date Drift

Date objects parsed from strings without timezone offset default to UTC midnight, causing drift in western timezones.

User's Point of View: "Every time I record a payment for my monthly bills, the next due date shifts backward by one day (e.g. from the 15th to the 14th). This means my bills keep showing up as due earlier and earlier."
  • Affected File: app/expenses/subscriptions/page.tsx (line 234)
  • Root Cause: `new Date(currentDateStr)` parses as UTC, evaluating to the previous calendar day local time in negative timezone offsets (e.g., US).
BUG 2.2 Timezone

Warranty Expiry Date Shift

Warranty expiration remaining days is computed based on local client vs UTC dates, showing incorrect expired states.

User's Point of View: "My item's warranty expiry date displays in the app as one day earlier than what I typed in, and the app tells me it is expired hours before the day actually ends."
  • Affected File: app/inventory/page.tsx (line 1270)
  • Root Cause: Calculations do not handle timezones or normalize offsets, causing local rendering shift on UTC date inputs.
BUG 2.3 Calendar

Monthly Habit Anchor Drift

Habits anchored on the 31st do not trigger during shorter months, breaking streaks.

User's Point of View: "If I have a monthly habit set for the 31st of the month, it never triggers in months like April, June, or February. This breaks my habit streaks and logs."
  • Affected File: lib/habit-scoring.ts (line 77)
  • Root Cause: Strict equality matching: `date.getDate() === anchor.getDate()` does not check if the date exceeds the month limit.

🔒 Database Integrity Bugs 2 Bugs

BUG 3.1 Integrity

Desynced Ledger Balances

Expense entries and liquidity balance updates are executed sequentially on the client without transaction protection.

User's Point of View: "Sometimes when I record an expense or pay a subscription, the money is deducted from my account but the expense log is not created, or the log is created but my balance is unchanged, throwing off my net worth."
  • Affected File: TransactionsForm.tsx (line 267)
  • Root Cause: Sequential async updates can fail halfway due to network drops, failing database atomic constraints.
BUG 3.2 Integrity

Odometer Calculations Reset to Zero

Calculations for average daily mileage and active vehicle odometer fallback incorrectly when component wear lists are empty.

User's Point of View: "My vehicle dashboard shows my current odometer reading as 0 or fails to predict my component wear if my parts do not have a specific distance limit set."
  • Affected File: app/vehicles/components/page.tsx (line 210)
  • Root Cause: `getCurrentVehicleOdo` sets values to 0 if a component has no limit set, ignoring initial registration configurations.

⚡ UI/UX & Form Bugs 3 Bugs

BUG 4.1 UX

Save Race Condition on Searchable Selects

Commit callback values in dropdown selections lag behind immediate form submission calls.

User's Point of View: "When I type a new category/subcategory and click save immediately, the page rejects my entry and tells me the field is required, even though I just typed it in."
  • Affected File: components/SearchableSelect.tsx (line 140)
  • Root Cause: 200ms timeout on input blur executes after the save button's click handler, failing initial validations.
BUG 4.2 UX

Blocked Weight inputs on Bodyweight Workouts

Workout saves enforce positive float formatting values for weights, prohibiting common shorthand.

User's Point of View: "When I try to log bodyweight exercises like pullups and write 'BW' or leave the weight blank, the app displays a weight validation error and rejects my log, forcing me to enter a fake weight."
  • Affected File: app/workout/page.tsx (line 480)
  • Root Cause: The form validation enforces `parseFloat(s.weight)` must be a valid number, which prevents text inputs like `"BW"`.
BUG 4.3 UX

Invisible Second Brain Links

Connections created between knowledge base cards are never fetched or displayed in the UI details panel.

User's Point of View: "I can click to link notes together in the second brain, but these connections are completely invisible and never show up on my notes or cards page."
  • Affected File: hooks/useBrain.ts (line 178)
  • Root Cause: Hook function `getLinks` fetches cards connections from the DB, but it is never referenced or rendered on the cards page.

📊 Performance & Scale Bugs 4 Bugs

BUG 5.1 Performance

Page Load Stutter (Sequential Updates)

Task updates evaluated on page load execute database PATCH updates sequentially within a loop.

User's Point of View: "Whenever I load my tasks or open the app dashboard, the app freezes or stutters for a second because it runs multiple database operations in a slow, consecutive loop."
  • Affected File: lib/task-recurrence.ts (line 102)
  • Root Cause: The code updates `is_today` and `is_week` flags for multiple tasks sequentially in a `for` loop on mount, hitting network congestion.
BUG 5.2 Performance

Sluggish Cards Dashboard Load

Opening the Second Brain retrieves the entire database links list to construct counts in client memory.

User's Point of View: "As my Second Brain grows, opening the cards dashboard becomes slower and slower, making the app feel heavy and laggy."
  • Affected File: app/second-brain/cards/page.tsx (line 194)
  • Root Cause: `loadAllLinksCount` fetches the entire `brain_links` table into memory to map card connections, leading to high data overhead.
BUG 5.3 Analytics

Statistical Bias (Excluded Zero Values)

Correlation charts filter out `0` values from calculations, inflating averages and skewing reports.

User's Point of View: "My health and finance reports display inflated averages and skewed charts because days where I spent zero money or logged 0 steps/water are ignored in calculations rather than counted as zero."
  • Affected File: app/reports/correlations/page.tsx (line 128)
  • Root Cause: `xVal > 0` checks exclude `0` values from correlations, and `parseFloat(row.value) || null` treats `0` logs as missing values.
BUG 5.4 Crash Risk

Edge Subrequest Send Limits Exceeded

Broadcast notifications dispatch push requests concurrently via `Promise.all` which triggers rate limit issues on Edge.

User's Point of View: "When notifications are sent out, many of my registered devices do not receive them, or the system crashes halfway through sending."
  • Affected File: app/api/push/send/route.ts (line 112)
  • Root Cause: Cloudflare Worker subrequest limits restrict concurrent fetches. Resolving notifications via `Promise.all` breaks worker constraints.
